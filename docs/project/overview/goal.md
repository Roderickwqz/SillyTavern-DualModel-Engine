# 项目目标

## 项目定位

SillyTavern DualModel Engine 是面向单人、本机、一对一角色扮演的 SillyTavern 扩展。项目把负责剧情表达的 Narrator 与负责结构化状态维护的 Recorder 分离，减少长篇 RP 中遗忘事实、状态漂移、数值判定前后矛盾等问题。

扩展通过 Git URL 安装，复用 SillyTavern 的 Connection Profiles、事件系统和同源聊天存储 API，不运行独立后端，也不保存模型凭据。

## 目标用户

- 希望长期 RP 状态可持续、可审计的 SillyTavern 用户。
- 需要把剧情生成与状态维护交给不同模型的本机单人用户。
- 希望使用轻量 D20 或声明式自定义规则，但不想部署额外服务的用户和扩展开发者。

## 核心目标

1. 在 Narrator 生成前注入当前权威状态，在回复结束后由 Recorder 生成并校验状态 Patch。
2. 为 swipe、继续生成、重生成、消息删除、消息编辑、重算和聊天切换维护正确的分支状态。
3. 提供由代码和 Web Crypto 驱动的 D20 判定、伤害结算与不可变审计记录，避免模型自行编造骰点。
4. 支持纯剧情状态、内置轻量 D20 和可导入的声明式自定义规则预设。
5. 在 Recorder 输出无效、请求取消、结果过期或宿主保存失败时，保留最后一个有效状态并回滚内存修改。
6. 保持部署简单：用户只需安装扩展并选择 Recorder Connection Profile，不需要 npm、数据库或额外后端。

## 产品边界

- 首版只支持单用户、单活动页面和一对一角色聊天；群组聊天保持禁用且不写入插件状态。
- 依赖 SillyTavern 1.18.0 及以上版本提供连接、事件、工具调用和聊天持久化能力。
- 不提供多人协作、跨设备同步、独立云存储或独立模型代理。
- 不接管 Narrator 的主连接，不在扩展中保存 API Key、代理凭据或模型凭据。
- 可以与官方 D&D Dice 共存，但 DualModel Engine 的正式判定、角色状态和分支审计以自身规则记录为准。

## 成功标准

- 用户可通过 Git URL 安装，并在没有运行时构建步骤的情况下加载已提交的 `dist` 产物。
- 用户可为 Recorder 选择独立 Connection Profile，并在一对一聊天中启用扩展。
- 状态、规则记录和活动分支在刷新或重新载入聊天后保持一致。
- 普通剧情、D20、自定义预设、swipe、继续生成、删除、编辑和重算流程结果一致且可恢复。
- 所有写入具备失败回滚和陈旧任务保护；错误不会破坏最后有效快照。
- 自动化测试、构建和发布产物可重复性检查持续通过；真实宿主发布前完成可选 E2E 与手工模型/代理清单。
